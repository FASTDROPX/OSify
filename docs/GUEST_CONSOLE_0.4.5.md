# OSify 0.4.5 — управление, PiP, настройки и каталог

4 ноября 2026. Версия 0.4.5, code 12; Android 8+ / ARM64 и x86_64.

## Изменения

- Fullscreen скрывает заголовок и системные строки, сохраняя управление. В альбомной ориентации панель вертикальная справа. Исправлен контраст иконок плавающей панели тёмной темы.
- Android «Назад» открывает Material меню: скрыть экран, настоящий Android PiP, остановить машину и отменить. В PiP показывается живой экран; раскрытие возвращает управление той же ОС. Потеря фокуса отпускает клавиши, соединение сохраняется. Закрытие PiP скрывает экран, машина продолжает работать в службе.
- Меню остановленной машины → «Изменить конфигурацию»: название, RAM и ядра ползунками, BIOS/UEFI. Ползунки также используются при создании. Работа с ползунками скрывает клавиатуру, форма учитывает её высоту. Изменения применяются при следующем запуске. Существующие диск, исходный образ, порт и секрет доступа сохраняются; ёмкость существующего диска не меняется. SQL запрещает менять работающую машину, запуск перечитывает свежие настройки под тем же mutex. RAM — до половины памяти телефона и 4096 MiB, CPU — 1–4.
- «Логи машины · TXT» в меню экрана и «Журнал движка» в Launcher: обновить, копировать, сохранить через системный диалог или отправить через Android Share. Логи находятся в закрытом каталоге машины: события OSify, stdout/stderr QEMU, serial гостя; сохраняется хвост предыдущей сессии. QEMU и события ограничиваются; serial хранится за текущую сессию. Экспорт ограничивает каждый раздел последним 1 MiB, скрывает известные секреты VNC/операции и внутренний путь приложения. FileProvider открывает только созданные TXT из cache/vm-log-exports; широкое разрешение на хранилище не требуется.
- «Собрать журнал Linux» готовит в редакторе команду journalctl/dmesg/сети с выводом в /dev/ttyS0. Её надо выполнить в консоли гостя, проверив и нажав Enter. VGA-текст автоматически не считывается. Приложение отдельно не пишет нажатия/буфер; serial может содержать вывод самой ОС.
- Для Linux используется VirtIO NIC через user-mode NAT QEMU; для Windows сохранена RTL8139. В live-образе может требоваться поднять интерфейс и включить DHCP в самой ОС. Сетевая проверка: DHCP выдал 10.0.2.15, DNS example.com разрешился; ручной HTTP wget -T8 завершился таймаутом, полноценный TCP/HTTPS доступ пока не подтверждён.
- Закрытие каталога использует ту же геометрию и длительность 760 мс, что открытие, с обращённой во времени кривой. Прокрутка перед закрытием возвращается плавно, повторные нажатия не создают конкурирующие анимации. Описание фиксировано в 12 sp / 17 sp: две конечные раскладки постоянной ширины скрываются и проявляются у концов перехода. Размер шрифта и переносы не прыгают посередине. Заголовок масштабируется без промежуточной перевёрстки.
- Приветствие не изменено; каталог, настоящие изображения и соответствующие исходники нативных зависимостей сохранены.

## Ошибки Arch Linux на скриншоте

Network Name Resolution — отказ systemd-resolved (разрешение имён), Rule-based Manager for Device Events and Files — systemd-udevd (события устройств). Повторения означают неудачные повторные запуски служб. Один экран не доказывает причину: нехватку RAM, проблему CPU или драйвера. Известная конфигурация: Arch Linux, 1024 MB и 3 ядра. Для точной диагностики нужен журнал этих служб и ядра; теперь его можно собрать в TXT. Исправление сбоев именно этого образа Arch пока не подтверждено.

Источники: [systemd-resolved](https://www.freedesktop.org/software/systemd/man/latest/systemd-resolved.service.html), [systemd-udevd](https://www.freedesktop.org/software/systemd/man/latest/systemd-udevd.service.html), [Android PiP](https://developer.android.com/develop/ui/views/picture-in-picture), [QEMU networking](https://www.qemu.org/docs/master/system/devices/net.html).

## Проверки

- JVM app + core: 64 теста, 62 прошли, 2 условных host-QEMU пропущены; ошибок нет. Проверены сохранность диска при редактировании, запрет изменения работающей VM, безопасные пути логов, удаление секретов, ротация, постоянные переносы описания и обратная геометрия карточки.
- Android API35 x86_64, настоящая Alpine: прошли тесты нормального шрифта (121.397 с) и 135% (122.278 с): root, вставка и прямой ввод, мышь/клавиши, fullscreen с панелью, правая панель, настоящая PiP с возвратом и успешной командой после раскрытия, QMP Stop; реальные TXT и доступ через FileProvider.
- Настройки/TXT: изменение 512 → 768 MB и 1 → 3 ядра сохранилось, данные диска остались прежними. Настоящий TXT в Downloads проверен чтением. Android Share открылся, отправки кому-либо не было. Первый тест прошёл за 14.768 с; итоговый повтор вместе с каталогом — 2 теста за 28.25 с.
- Каталог: JVM проверил промежуточную геометрию и неизменные fontSize/width/переносы описания; Android тест возврата и закрытия после прокрутки прошёл. Итоговый повтор каталог + настройки: 2 теста за28.25 с. Подписанный APK отдельно проверен с полными анимациями вне тестового часовщика.
- Release R8 и lintRelease прошли. Lint: 0 ошибок, 40 предупреждений. Подписанный APK обновился без удаления данных; конечный APK запустил загрузку Alpine до ядра/OpenRC, прямой текстовый ввод отображался в госте, остановка вернула готовую машину в Launcher. Полный вход root, fullscreen и HTTP дополнительно проверялись на предшествующей подписанной сборке с тем же кодом экрана/движка; последняя правка касается только прозрачности бейджа каталога. Аварийный буфер пуст..
- Подпись v2/v3 и zipalign -P16 проверены; исходники ZIP проходят CRC и соответствуют текущим файлам.

## Установка и ограничения

APK: 20,839,014 байт, SHA-256: 051b92280fa332548ac9bb77dcbb0080e94bcee33efd5237cc483ac48ffc8bd5.

Тот же локальный сертификат, что у выданных здесь 0.4.2–0.4.4: 5a430f433d75d0d54a41647ef97bc13ee682dbcee2ee0693876e6e76071b32d9. Обновление сохраняет данные. Ключ оригинального 0.4.1 отсутствовал в архиве: для обновления поверх оригинала нужен его ключ. Удаление приложения удаляет его диски.

Физический ARM64/16 KB телефон, USB/Bluetooth и установка Windows в этой проверке не использовались. Эмуляция программная, без KVM. Нативные upstream библиотеки имеют 4 KB ELF, включён pageSizeCompat; собственный JNI выровнен на 16 KB. PiP зависит от поддержки и разрешения Android; для ввода маленькое окно нужно раскрыть. «Остановить» немедленно завершает VM через QMP quit; для штатного завершения используйте питание внутри ОС. Журнал serial не заменяет полный journal гостя.
