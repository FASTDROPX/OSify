# Launcher и отрисовка — OSify 0.4.0

В панели пять вкладок; Launcher находится в центре. Каталог выбирает источники, «Загрузки» хранят и импортируют файлы, Launcher создаёт и запускает машины. Старые кнопки запуска из коллекции и главного экрана убраны. Настройки ведут в Launcher для подготовки движков.

## Запуск своего Tiny 11 / Linux ISO

1. Termux нужен отдельно: [F-Droid](https://f-droid.org/en/packages/com.termux/). Откройте его один раз.
2. Launcher → Подготовка → Скопировать команду подготовки. Вставьте в Termux:
   ```sh
   mkdir -p ~/.termux && printf '\nallow-external-apps=true\n' >> ~/.termux/termux.properties
   ```
3. Вернитесь в OSify, включите интеграцию, выдайте разрешение внешних команд. Снова нажмите подготовку для установки пакетов. Настройка RUN_COMMAND даёт приложению возможность запускать команды в Termux; включайте её только для доверенных приложений.
4. Импортируйте ISO в «Загрузках». Launcher поддерживает загрузочные x64 ISO. Факт импорта не гарантирует загрузочность или безопасность произвольного образа.
5. Создайте VM с Windows или Linux. Выберите BIOS либо UEFI + TPM 2.0 под требования образа. Создаётся отдельный разреженный QCOW2. Для начала Linux достаточно 512–1024 MiB; для Windows ресурсы зависят от сборки, обычной Windows 11 нужно больше. Приложение не обходит требования Windows.
6. Выберите «С ISO», запустите и откройте экран. Первая передача большого ISO может занять время; индикатор ожидания не считается прогрессом загрузки гостя. Не выключайте Termux во время копирования.
7. Установите гостя на диск. Для следующих стартов выбирайте «С диска». После выключения гостя при необходимости остановите уже завершённый QEMU через Launcher; состояние внешнего процесса не опрашивается постоянно.

Экран подключается к настоящему VNC QEMU на loopback, с паролем отдельной VM. Поддерживает касание/перетаскивание, ПКМ/долгое нажатие, двухпальцевую прокрутку, pinch и перемещение увеличенного экрана, экранную и аппаратную клавиатуру. SPICE, звук, аппаратный 3D, общие папки и USB passthrough не реализованы. Графический экран автоматически не открывается, пока пользователь не нажмёт «Открыть экран».

«Нет ответа?» только сбрасывает ожидание callback. Установку пакетов или запущенную VM это не останавливает; копирование ISO прерывается. Перед сбросом проверьте Termux. Устаревшие callbacks после сброса игнорируются.

Все файлы машины в Termux находятся в `$PREFIX/var/lib/osify/<id>` (ID показан при удалении записи). «Убрать» доступно для остановленной VM, удаляет только запись Launcher. Для освобождения места удалите соответствующий каталог в Termux после проверки его содержимого. Удаление OSify не очищает Termux. ISO, связанный с записью VM, защищён от удаления в «Загрузках» до удаления записи.

## Отрисовка

- Обновления RAM и счётчиков загрузок собираются внутри своих карточек. Корневая страница не подписана на полный поток памяти и загрузок.
- Анимация входа меняет положение и прозрачность уже измеренных элементов; размеры страницы не пересчитываются на каждом кадре. Перевод перемещения только в transform давал обрезание текста в промежуточных native-кадрах и не включён в итоговую сборку.
- Шапка остаётся неподвижной; Navigation Flow сохраняет морфинг и содержит пять вкладок.
- Сохраняются draw-only волны и кэширование целевой цветовой схемы. Запрос высокой частоты не отменяет энергосбережение и ограничения Realme.
- В экспорт диагностики включены реальные Window FrameMetrics: p50/p95 времени кадра, превышения deadline, потерянные callback метрик. Это не синтетический счётчик FPS и не замер 120 FPS на телефоне.

## Реализация и проверки

Room 1 → 2 добавляет таблицу VM без разрушительного сброса. Команды не принимают произвольные engine flags, имена VM не подставляются в shell. ISO передаётся по одноразовому случайному loopback URL, проверяется SHA-256, затем атомарно переименовывается. Разрешена только одна передача ISO в Termux одновременно. VNC не публикуется наружу. QMP работает через приватный Unix-сокет; управление затрагивает только каталог соответствующей VM.

QEMU, прошивка EDK2/SeaBIOS, swtpm и proot-distro не распространяются внутри APK. Termux устанавливает их из официальных репозиториев. В этой среде проверены метаданные Termux QEMU 11.1.3, proot-distro 5.10.3 и swtpm 0.10.2; это не утверждение о версии на телефоне пользователя.

Реальные испытания на хосте: Alpine x86_64 до оболочки с `uname -a`, Windows 11 Evaluation до окна Windows Setup, настоящий парольный VNC через производственный RfbClient, QMP stop/cont. Хост использует QEMU 10.0.13. Полная установка Windows, Android → Termux → QEMU на Realme, OEM-фоновые ограничения, TPM/UEFI на телефоне и 120 FPS на устройстве не проверены. Нельзя переносить успех хостового теста на эти сценарии.

Кадры UI получены native-рендером Robolectric; отдельно сохранены реальные кадры QEMU. Они явно различаются по каталогу и описанию в `docs/evidence/runtime-0.4.0`. ISO и сторонние бинарники в архив исходников не включаются.
