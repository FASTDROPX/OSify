# OSify 0.4.12 — изменения и аудит загрузки

Дата: 4 ноября 2026. Версия 0.4.12, versionCode 19. Готовый APK подписан тем же ключом, что предыдущие версии. Исходный проект находится в `work/osify-source/osify`.

## Добавленные удобства

- **Обмен файлами:** Launcher → меню машины → «Файлы и драйверы». В работающей ОС этот диалог доступен из меню управления. Добавленные Android-файлы записываются на отдельный ISO9660/Joliet CD **PHONE**. Unicode-имена сохраняются. Это копии, исходные файлы телефона не изменяются. После обновления CD гостю может понадобиться повторно открыть или перемонтировать его.
- **Обратная передача:** откройте `OSify-Files.url` с PHONE в браузере гостя. Выберите файл и отправьте его; в OSify появится кнопка сохранения через системное окно Android. Нужна работающая NAT-сеть внутри гостя. Адрес приватный для машины. До 128 МБ на файл; до 512 МБ принятых файлов. Сохранённые копии можно удалять из обмена отдельной кнопкой.
- **Избранное:** звезда на карточке каталога и отдельный фильтр «Избранное». Выбор сохраняется, остальные фильтры и сортировка продолжают работать.
- **Поиск Launcher:** поиск по названию машины, семейству и названию исходного образа; очистка поля и закрытие клавиатуры через поиск.
- **Клонирование:** меню остановленной машины → «Клонировать машину». Копируются виртуальный диск, параметры и собственный OVMF VARS. Новые ID, порт и пароль; приватные данные обмена и журналы оригинала не копируются. Есть прогресс и отмена. База получает новую машину только после завершения копирования.
- **Драйверы Windows:** отдельный CD, официальный VirtIO-Win 0.1.302 или импорт собственного ISO. Диск можно подключать/извлекать во время работы. Установка драйверов выполняется в гостевой Windows и не переключает контроллер существующего системного диска. Для VirtIO-сети выберите соответствующий адаптер в Advanced остановленной машины, затем установите его драйвер с CD в Windows.
- **Подгонка экрана:** пропорциональное вписывание и сброс увеличения при изменении размера окна/повороте. Автоподгонку можно отключить в меню управления.
- **Разрешение внутри гостя:** дополнительный помощник с PHONE отслеживает размер доступной области телефона. Windows 7+ требует PowerShell **3 или новее**; Linux — X11, Python 3 и xrandr. Применяются только поддерживаемые видеодрайвером режимы. Помощник не устанавливается скрыто. XP и Wayland этим помощником не поддерживаются. Без него меняется масштаб изображения на телефоне, а не разрешение гостя.

## Как установить помощник разрешения

Windows: скопируйте файлы `OSify-*` с PHONE в доступную для записи папку и запустите `OSify-Install-Windows.cmd`. Настройка добавит помощник в автозагрузку текущего пользователя. Удаление: удалить `OSify Display.cmd` из папки автозагрузки.

Linux X11: `python3 OSify-Display.py --install`. Удаление: убрать `~/.config/autostart/osify-display.desktop`. Оба помощника сообщают фактическое разрешение и отказ видеодрайвера; приложение не выдаёт желаемое разрешение за применённое. Возможность конкретных портретных режимов зависит от гостевого драйвера.

## Найденные ошибки и изменения кода

| Место | Причина / исправление |
|---|---|
| `core/.../SupplementalDownloads.kt`, `BootPlan.kt`, `VmHardware.kt` | XP x86 ошибочно имел метаданные x64 и общий профиль. Добавлена архитектура X86; для новых XP: BIOS, pc, qemu32, IDE, cirrus, PS/2, включённый TSC. Начальная рекомендация — 512 МБ и одно ядро. |
| `app/.../ImageRepository.kt`, `engine/VmBootFiles.kt`, `core/.../BootMedia.kt` | Импорт не определял архитектуру, а запуск опирался на метаданные. Теперь ограниченное чтение фактического файла: ISO9660, каталог El Torito, EFI FAT/PE, признаки I386/AMD64, заголовок QCOW2. ARM64-only образ не запускается через x86 QEMU. Неизвестная архитектура требует явного выбора, а не угадывается. |
| `engine/NativeQemuEngine.kt`, `VmBootFiles.kt` | Исходный ISO требовался и при загрузке существующего установленного диска. Теперь ISO нужен только для действительного CD-старта/первичного импорта диска. Отсутствие, неполная копия, пустой/неоднозначный диск сообщаются до запуска. |
| `core/.../VmHardware.kt`, `engine/QemuService.kt` | Неявные номера устройств и общий порядок загрузки могли конфликтовать с дополнительными CD. Основной диск и установочный ISO получили собственные устройства и bootindex. PHONE и драйверы отдельные, исключены из автоматического boot fallback. Shell не используется: JNI получает массив аргументов. |
| `engine/QemuService.kt` | Копирование firmware стало атомарным из доверенных ресурсов APK. Существующий файл VARS каждой машины сохраняется. BIOS/UEFI установленной машины автоматически не переключается. |
| `core/.../BootPlan.kt` | Для новых Windows 11/Tiny11 x64 выбран Nehalem вместо qemu64: модель qemu64 в QEMU 5.1 не содержит SSE4.2/POPCNT, которые есть у Nehalem. Это настройка набора инструкций, не доказательство загрузки всех сборок Windows. |
| `engine/NativeQemuEngine.kt`, `QemuService.kt` | Ошибки загрузки библиотеки могли ошибочно считаться успешным завершением. Успешен только точный штатный результат JNI; добавлено наблюдение за исчезновением собственного QEMU-сервиса. Долгая загрузка или неподвижная картинка не объявляются зависанием. |
| `core/.../RfbClient.kt` | Реальный тест выявил потерю символов при мгновенной отправке длинной вставки в PS/2. Нажатия/отпускания дозируются; запросы обновления изображения не ждут окончания вставки. |
| `engine/NativeQemuEngine.kt` | У встроенного QEMU 5.1 команда `blockdev-change-medium` не принимает `force`. Используется поддерживаемый `eject(force)` и затем смена носителя без этого параметра. |
| `engine/VmLogs.kt` | Экспорт содержит фактические архитектуру/CPU/прошивку, устройства, пути/размеры и аргументы QEMU; пароли, токены и приватный адрес обмена маскируются. |

Новые файлы: `BootMedia.kt`, `BootPlan.kt`, `ExchangeIso.kt`, `GuestBridge.kt`, `DriverDownloads.kt`, `VmBootFiles.kt`, `GuestTools.kt`, `GuestToolsDialog.kt`, два помощника в `assets/guest-tools/`.

Используемый движок — встроенный Limbo QEMU 5.1 через JNI и приватный Android-сервис. Старые Termux-классы не участвуют в этом пути запуска. Применяется программная TCG-эмуляция. В APK нет ARM64-гостевого QEMU; ARM64 телефона является архитектурой хоста и не делает ARM64 ISO совместимым с x86-эмулятором.

## Проверки и фактические результаты

- Оригинальный файл пользователя `en_windows_xp_professional_with_service_pack_3_x86_cd_vl_x14-73974.iso`, 617 754 624 байта, проверен только чтением. SHA1: `66ac289ae27724c5ae17139227cbe78c01eefe40`. Определены x86 и Legacy BIOS, EFI-загрузки нет.
- На Android API 35 x86_64 эмуляторе **этот XP ISO дошёл до Windows XP Professional Setup / Welcome to Setup**, 512 МБ, одно ядро, BIOS, pc, qemu32, cirrus. Есть скриншот. Полная установка, последующая загрузка рабочего стола и работа XP на физическом ARM-телефоне не подтверждены.
- Реальный Alpine загрузился через BIOS; гостевой процесс прочитал текст с PHONE и отправил файл обратно через NAT/HTTP. В тестовой чистой Alpine требовалось сначала включить eth0 и получить DHCP; это не установка драйвера Android.
- Финальный гостевой тест обмена прошёл за **122,612 с**: чтение PHONE, обратная передача, горячее обновление CD, чтение нового файла, подключение тестового ISO в отдельный слот драйверов, подтверждение через QMP и извлечение. Финальный UI-тест прошёл за **25,797 с**, включая проверку полного отображения подписи «Драйверы».
- Независимая библиотека pycdlib прочитала Unicode-имя и содержимое созданного Joliet ISO. Проверен настоящий HTTP multipart roundtrip двоичных данных и изоляция приватного адреса.
- Тесты копии диска/NVRAM, отмены, запрета клонирования работающей машины, независимых секретов, загрузки установленного диска без ISO, сохранения избранного, границ размеров экрана и маскирования логов прошли.
- Матрица аргументов: XP x86 BIOS; Windows 7 x64 BIOS; Windows 10/11 x64 UEFI; Linux x64 BIOS. Проверены отказ ARM64 без соответствующего движка, конфликт прошивки/носителя, усечённый ISO и неверный QCOW2. Это проверки конфигурации, не реальные загрузки перечисленных Windows.
- UI: реальное избранное и фильтр, поиск, клонирование кнопкой, вкладки инструментов в обеих ориентациях; сохранены скриншоты. Для портретных подписей используется подгонка в одну строку, для горизонтального окна — компактный заголовок и прокрутка содержимого.
- R8 release / lintVital сборка прошла. Полный регрессионный набор и длительные установки всех ОС не запускались.

### Ограничения загрузочного аудита

`tiny11a64 r1.iso` указан по имени, самого файла на этом компьютере нет. Наличие `BOOTAA64.EFI` на прежнем скриншоте указывает на ARM64-загрузчик, но без проверки всего этого носителя не доказывает его архитектуру целиком или повреждение. Для точной причины нужны сам ISO либо экспорт журнала новой попытки с телефона. Загрузка этого Tiny11 не подтверждена.

UEFI/Q35/Nehalem + Alpine был реально проверен до запуска GRUB через OVMF. За 100 секунд гостевой Linux не дошёл до login; причина не установлена. Не выдаём этот сценарий за успешную полную загрузку и не меняем существующие машины на Q35 автоматически.

Помощники изменения разрешения реализованы, однако работа с видеодрайверами всех гостевых Windows/X11 не проверена. Масштабирование на телефоне и запрос нужного размера не гарантируют, что гостевой драйвер поддержит произвольное разрешение.

## Для уже созданной XP

Остановите машину и откройте её параметры. Не меняйте прошивку уже установленной системы без понимания способа её установки. Для новой установки указанного x86 ISO используйте BIOS, 512 МБ, одно ядро; Advanced: x86, pc, qemu32, IDE, cirrus, TSC On, USB Off. После установки выберите загрузку с установленного диска. Не удаляйте существующий диск ради смены параметров.

## Источники

- [Определения CPU QEMU 5.1](https://github.com/qemu/qemu/blob/v5.1.0/target/i386/cpu.c): наборы инструкций qemu64 и Nehalem.
- [VNC QEMU 5.1](https://github.com/qemu/qemu/blob/v5.1.0/ui/vnc.c): встроенный сервер не даёт универсального механизма изменения разрешения гостя одним клиентским запросом, поэтому используется явный гостевой помощник.
- [Документация образов QEMU](https://www.qemu.org/docs/master/system/images.html): форматы дисков; обмен сделан через отдельный CD и локальную страницу, без совместной записи Android и гостя в один файловый образ.
- [VirtIO-Win: установка драйверов](https://virtio-win.github.io/Knowledge-Base/Driver-installation.html), [проект сборки](https://github.com/virtio-win/virtio-win-pkg-scripts), [выбранный ISO 0.1.302](https://fedorapeople.org/groups/virt/virtio-win/direct-downloads/archive-virtio/virtio-win-0.1.302-1/virtio-win-0.1.302.iso). Сервер отдаёт ISO 877 373 440 байт. В проверенном каталоге не найдена опубликованная SHA-256 этого ISO: используется строго ограниченный HTTPS-источник, после загрузки вычисляется локальный SHA-256. Проверка подписи/контрольной суммы издателя не заявляется. Целиком этот ISO в рамках теста не скачивался; горячее подключение проверяется на отдельном тестовом ISO.

Обложки, логотипы, NixOS-ресурсы, шрифты, палитра, onboarding, Navigation Reflow и анимация запуска/остановки не заменялись. Ранее удалённый шумный детектор ошибок не возвращён. Исходные изображения побайтно сверены с началом этой доработки.
