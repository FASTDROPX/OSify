# OSify 0.3.3

## Частота экрана и производительность

В предыдущем коде не было фиксированного таймера 60 FPS, но не было и явного запроса высокой частоты для интерфейса. Compose использует часы кадров Android. Наличие 120 Гц у панели само по себе не означает 120 отрисованных кадров приложения.

Теперь MainActivity запрашивает наибольшую поддерживаемую частоту при текущем разрешении через preferredRefreshRate. При энергосбережении явное предпочтение снимается. На Android 16 включён touch boost; DecorView и фактический AndroidComposeView используют REQUESTED_FRAME_RATE_CATEGORY_HIGH. Это официальный запрос системе, не обход политики Realme, нагрева или режима батареи. Android учитывает голос View, когда он требует перерисовки; это не постоянный таймер перерисовки пустого экрана.

Движение волн RAM и передачи перенесено в фазу рисования: обновление фазы не запускает повторную композицию Canvas на каждом кадре. Типографика и целевые палитры кэшируются. При переходах страниц состояние анимации по-прежнему читается на этапе размещения, без повторного измерения всего списка на каждом кадре.

В диагностику добавлена текущая частота режима дисплея с явным пояснением, что это не измеренные FPS приложения. На физическом Realme FPS, пропуски дедлайнов и p95 времени кадра в этой среде не измерены. Причина исходных ощущений пользователя не считается доказанной. Для дополнительных аппаратных замеров полезны FrameTimeline/Perfetto на устройстве.

Документация Android: https://developer.android.com/develop/ui/views/animations/adaptive-refresh-rate

## Верхний край списка

Жёсткая видимая граница под неподвижной шапкой закрыта градиентом ScrollFade высотой 28 dp: цвет текущей поверхности плавно переходит в прозрачность. При прокрутке интенсивность нарастает на первых 24 dp, при начале списка отсутствует. Слой не перехватывает нажатия. Цвет берётся из анимированной палитры, поэтому соответствует фирменной, динамической и AMOLED-теме.

## Темы

Все 48 цветовых ролей Material 3 интерполируются единым transition: 600 мс для полного движения, 120 мс для reduced, мгновенно для off. Повторное переключение до завершения продолжает переход от текущего значения. Типографика не создаётся заново на каждом кадре. uiMode обрабатывается без пересоздания Activity, чтобы системная смена светлой/тёмной темы также могла пройти через Compose-переход. Статусные значки меняют контраст при пересечении порога яркости поверхности.

Новая сохранённая настройка «AMOLED» доступна в Настройки → Оформление. В любой тёмной палитре фон и базовая поверхность становятся #000000, тональные карточки — нейтральными почти чёрными. Акценты, в том числе выбранные из обоев, сохраняются. В светлой теме чёрный фон не применяется; выбор AMOLED остаётся сохранён для следующего включения тёмной темы.

## Проверки

Robolectric API 34: проверены промежуточный цвет светлая → тёмная, конечные палитры, истинно чёрный фон в фирменной и динамической AMOLED-теме, отключённое движение, сохранение AMOLED и сброс. Получены PNG рендеры перехода темы, AMOLED и прокрученных настроек с затуханием. Существующие проверки страниц, фиксированной шапки, навигации, загрузок и данных сохранены. Физического устройства с экраном 120 Гц в среде нет; результаты сборки не являются доказательством 120 FPS.

APK полный, подписывается прежним сертификатом по v1/v2/v3 и проверяется для API 36. Запуск ISO/QEMU этим обновлением не добавлялся.

Итог: 38 тестов пройдено, 0 errors, 24 warnings. Логи и кадры находятся в `docs/evidence/ui-0.3.3`.
